# Audit: Next.js API Proxy for Backend Connection

**Date**: 2026-10-02  
**Commit topic**: nextjs-api-proxy  
**Severity**: Low

## Review Summary

Reviewed Next.js API proxy route implementation for connecting Vercel-deployed frontend to Render-deployed backend.

## Findings

### 1. API Proxy Implementation - VERIFIED ✓
**Severity**: None  
**Evidence**: `apps/web/app/api/[...path]/route.ts`
- Catch-all route forwards all `/api/*` requests to backend
- Supports all HTTP methods (GET, POST, PUT, PATCH, DELETE)
- Proper header forwarding and filtering
- Standard Next.js App Router pattern
**Mitigation**: None needed - correct implementation

### 2. Environment Variable Configuration - CONFIGURATION REQUIRED
**Severity**: Medium  
**Evidence**: Line 3: `process.env.NEXT_PUBLIC_API_URL || 'http://127.0.0.1:8000'`
- Requires `NEXT_PUBLIC_API_URL` to be set in Vercel
- Falls back to localhost for development (good)
- If not set in production, will try to reach localhost and fail
**Mitigation**: Document requirement clearly and verify it's set in Vercel before deployment

### 3. Credential Forwarding - VERIFIED ✓
**Severity**: None  
**Evidence**: Line 43: `credentials: 'include'`
- Forwards cookies for authentication
- Required for session-based auth with MongoDB
- Correct for same-origin or properly configured CORS
**Mitigation**: None needed - required for authentication

### 4. Error Handling - ADEQUATE
**Severity**: Low  
**Evidence**: Lines 56-62
- Catches fetch errors and returns 502
- Logs error to console
- Generic error message to client
**Mitigation**: Consider more specific error messages for debugging (but don't leak backend details to client)

### 5. Header Filtering - VERIFIED ✓
**Severity**: None  
**Evidence**: Lines 31-35
- Filters out `host`, `connection`, `content-length`
- Prevents proxy loop and connection issues
- Standard proxy pattern
**Mitigation**: None needed - correct implementation

### 6. Body Handling - VERIFIED ✓
**Severity**: None  
**Evidence**: Lines 37-38
- Uses `.text()` for body to handle any content type
- Skips body for GET/HEAD requests
- Forwards as-is to backend
**Mitigation**: None needed - flexible approach

### 7. CORS Implications - POTENTIAL ISSUE
**Severity**: Medium  
**Evidence**: Proxy sits between frontend and backend
- Backend CORS `ALLOWED_ORIGINS` must include Vercel domain
- Proxy forwards Origin header to backend
- If CORS not configured, requests will fail
**Mitigation**: Ensure `ALLOWED_ORIGINS` in Render includes Vercel domain

## Security Considerations

1. **Open proxy risk**: This proxy forwards ANY request under `/api/*` to the backend
   - Not a security issue if backend has proper authentication
   - Backend is responsible for access control
2. **Header forwarding**: Forwards most headers including cookies and auth tokens
   - Required for authentication
   - Backend should validate these
3. **Error messages**: Generic 502 error doesn't leak backend information
   - Good for production security
   - May make debugging harder

## Not Tested

- Proxy with actual Vercel deployment not verified
- Authentication flow through proxy not tested
- File upload/multipart form data handling not verified
- Large request/response payloads not tested
- Streaming responses not tested

## Regression Risk

**Low**:
- Additive change (new file, no modifications to existing code)
- Only affects deployed Vercel frontend
- Local development unchanged (uses same API client code)
- If proxy fails, frontend shows clear error message

## Compliance Notes

This is NOT an exhaustive security audit. Changes involve:
- Proxying all API requests (potential for abuse if misconfigured)
- Cookie and authentication header forwarding
- CORS and same-origin policy implications

Recommend:
- Verify `NEXT_PUBLIC_API_URL` is set correctly in Vercel
- Verify `ALLOWED_ORIGINS` includes Vercel domain in Render
- Monitor proxy performance and error rates after deployment
- Consider rate limiting at proxy level if abuse occurs

## Recommended Actions Before Deploy

1. **Critical**: Set `NEXT_PUBLIC_API_URL` in Vercel environment variables to Render backend URL
2. **Critical**: Add Vercel domain to `ALLOWED_ORIGINS` in Render backend environment
3. Test authentication flow after deployment
4. Verify file uploads work through proxy
5. Monitor Vercel function logs for proxy errors
