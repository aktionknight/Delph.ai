# Review: timeline deliverables and human fine tuning

Parent observed: d1e017b. Review covers the final integrated feature described in the matching context record, including earlier feature changes already present in the parent. No Git commit was created by Codex. This is a targeted implementation review, not an exhaustive security audit.

## Findings, evidence and mitigation

- Medium — Generated media can contain visual or pronunciation errors despite a passing copy evaluation. Evidence: automatic evaluation checks source-grounded text; live TTS verified audio bytes without a listening review. Mitigation: image/audio previews, spoken-script inspection, explicit acknowledgement of all retained media before current-version approval, and version invalidation after revisions. Visual/speech quality benchmarking remains incomplete.
- Medium — Providers can exhaust all free capacity, and Gemini embeddings remain a separate dependency. Evidence: earlier Groq burst tests reached both model limits; live narration evaluation used real 20B-to-120B rate-limit recovery. Mitigation: ordered bounded routing/cooldowns, grounded repair limits and honest exhaustion errors. No deterministic content is substituted. Distributed quota coordination remains future work.
- Low — Historical timeline mapping can differ from the current edited schedule. Evidence: immutable snapshots survive objective changes and timeline regeneration. Mitigation: display original day/objective and changed/missing-schedule notice; new generation validates selected item ownership/platform/type, media rejects unmapped legacy assets. There is no automatic rescheduling of historical deliverables.
- Low — Custom prompts may request unsupported claims or attempt to bypass policy. Evidence: custom text reaches agent payloads in several generation paths. Mitigation: 2,000-character validation, operation-scoped preferences explicitly subordinate to source grounding/schema/safety, caption and narration evaluation, version-specific human review. This is defense in depth, not proof against prompt injection.
- Informational — Planning section approval must not permit content publication. Evidence: reviews carry section/revision and are stored separately from asset approval history; publication still checks the current passing asset version. Tests verify stale review rejection and edits invalidate current publication eligibility.
- Informational — Media changes must retain immutable history and clear authorization. Evidence: tests retain the exact prior image version when adding narration, require explicit all-media acknowledgement, and prevent publication after copy edits. New copy versions omit stale attachments while historical media stays downloadable by the owner.
- Informational — Narration must be evaluated as spoken content rather than a complete Reel. Evidence: live initial narration failed because Reel prompts expected captions; dedicated narration prompt and narration_only evaluator scope now exclude captions/storyboard requirements while maintaining grounding. Tests reject unsupported script claims and ensure failed drafts never reach TTS or persist a new asset version.
- Informational — X published length must include every field and separators. Evidence: live initial captions exceeded platform bounds. Dedicated XPostContent validation rejects nonempty captions and enforces the newline-separated full 280-character boundary; provider fallback can replace invalid output.
- Informational — Credentials and ownership remain server-side. Media adapters use server configuration, voice names are allowlisted, authenticated media lookup checks owner-bound storage, and .env remains ignored. No secrets were printed, staged by Codex or placed in records.
