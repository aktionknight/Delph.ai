# Add Next.js API Proxy for Backend Connection

**Date**: 2026-10-02  
**Parent commit**: 19223ef

## Scope

Fix 404 errors in deployed Vercel frontend by adding a Next.js API proxy route that forwards requests to the Render backend.

## Problem

The frontend code makes API calls to `/api/*` paths, expecting Next.js to handle routing. Without an API proxy, Vercel returns 404 for all API requests because there's no route handler. The frontend needs to communicate with the FastAPI backend deployed on Render.

## Implemented Changes

### Frontend (`apps/web/`)

**app/api/[...path]/route.ts** - New Next.js catch-all API route:
- Proxies all `/api/*` requests to the backend configured in `NEXT_PUBLIC_API_URL`
- Supports all HTTP methods: GET, POST, PUT, PATCH, DELETE
- Forwards headers (excluding host, connection, content-length)
- Forwards request body for non-GET requests
- Preserves response status codes and headers
- Returns 502 error if backend is unreachable
- Falls back to `http://127.0.0.1:8000` for local development

## How It Works

1. Frontend calls `api("/auth/login", "POST", data)` from `lib/api.ts`
2. This becomes `fetch("/api/auth/login", {...})`
3. Next.js routes this to `app/api/[...path]/route.ts`
4. Proxy extracts path and forwards to `${NEXT_PUBLIC_API_URL}/auth/login`
5. Response from Render backend is returned to frontend

## Architectural Decisions

1. **Catch-all route `[...path]`**: Handles any API path without explicit routing
2. **Environment variable**: Uses `NEXT_PUBLIC_API_URL` for flexibility across environments
3. **Credential forwarding**: Passes cookies for authentication with `credentials: 'include'`
4. **Header filtering**: Removes connection-specific headers to avoid proxy issues
5. **Text-based body**: Uses `.text()` instead of `.json()` to handle any content type

## Configuration Required

### Vercel Environment Variable:
```
NEXT_PUBLIC_API_URL=https://your-backend.onrender.com
```

### Local Development:
Defaults to `http://127.0.0.1:8000` when `NEXT_PUBLIC_API_URL` is not set.

## Verification

After deployment with `NEXT_PUBLIC_API_URL` set:
- Frontend `/api/auth/login` → Backend `/auth/login` ✓
- Frontend `/api/campaigns` → Backend `/campaigns` ✓
- Frontend `/api/assets/123` → Backend `/assets/123` ✓

## Limitations

- Proxy adds latency (~50-200ms) vs direct backend calls
- Vercel serverless function timeout (10s default, 60s max on Pro)
- Does not handle WebSocket connections (streaming endpoints may need alternative approach)
