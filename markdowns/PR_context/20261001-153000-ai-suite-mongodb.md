## Scope and implemented changes

- Replace default deterministic generation with validated model calls for strategist, creative directions, marketing timeline, writing, evaluator, repair, analytics, campaign memory and visual planning.
- Gemini provider supports structured JSON, per-role models, embedding task types, finite vector validation, bounded transport timeouts and transient-status retries. Optional Groq routing supports JSON validation and independently selected content/evaluation models. Optional Cohere reranking validates returned indices.
- Document ingestion stores chunks/embeddings in MongoDB and retrieves semantically using cosine similarity. Original account-mode uploads are private binaries. Mongo GridFS is the default binary store; R2 is optional.
- Add Mongo-backed password accounts, hashed/revocable opaque sessions, private workspace ownership on all campaign/brand/asset reads and writes, profile editing, cookie protections and origin validation.
- Mongo aggregate writes are atomic transactions with optimistic revisions. Loaded brand dependencies participate in the write to reject a concurrent brand change racing publication. Records are checked against a 15 MiB history capacity before writing.
- Retain immutable asset versions, evaluations and human approval records. New edits, regenerated content and media require new approval. Media approval explicitly records that the human reviewed the new media. Context and author attribution are recorded per version.
- Add strategy history/editing, timeline editing/rebalance, source removal/download, AI hook drafts and promotion to separately evaluated review assets, cumulative metric import history, AI observations and learning revisions tied to metric revisions.
- AI experiments start with zero results. Only explicit demo mode generates simulated fixture results. No model output is presented as observed audience performance.
- Optional Gemini/Pollinations image generation and Edge/Gemini speech use server-side configuration. Binary type/size checks and private, owner-checked serving apply. Media preview and approval acknowledgment are connected to the existing editor.
- Persist background operation status/events and stream live job progress via SSE. Per-campaign active-job uniqueness is indexed in MongoDB. Failed jobs remain inspectable; abandoned jobs are marked failed after an inactivity timeout.
- Update frontend account/profile forms, generation labels, planning editors, experiment imports/promotions, analytics and media controls. Correct CTR percentage display.
- Add root environment template and setup/provider documentation. Development launcher loads root environment and remains noninteractive. Install repository hooks as required; existing CI already checks every commit pair.

## Architecture decisions

- The user's MongoDB request overrides the blueprint's PostgreSQL recommendation. One owner-scoped workspace per account is represented by aggregate ownership; team roles are deferred.
- Mongo stores campaign aggregates and asset aggregates, plus users/sessions/jobs. SQLAlchemy records remain only as an internal record carrier and SQLite demo adapter. Account mode never silently falls back to SQLite.
- Retrieval scans stored embeddings for the bounded MVP corpus instead of requiring a Mongo Atlas vector-search index or another vector database. Historical learning sources are excluded from factual claim grounding.
- Gemini-only operation needs only a Gemini key plus Mongo credentials. Groq/Cohere/Pollinations/R2 are optional configured integrations. Gemini 2.0 and the free/developer Groq Llama IDs in the proposed table are retired; defaults are current configurable replacements.
- Fixed safety/format validators remain alongside semantic AI evaluation because model approval cannot enforce publication authorization. Human approval is always version-specific.
- FastAPI background tasks handle execution, with Mongo providing durable status and a campaign lock. This is not a durable distributed execution queue.
